# Flux — Motion Studio

A native SwiftUI iPhone customization app: moving wallpapers, color themes, playful animations, and wallpaper exports. Minimum iOS 17.

**Delivery status:** this package contains the Xcode source project. It has not been compiled with the Apple SDK, installed on a device, signed, uploaded, or approved for TestFlight. It is not an IPA and does not include a TestFlight invite. Local validation checks are described in VALIDATION.md.

## Included

- Six deterministic animated wallpaper styles: Aurora, Liquid, Orbit, Prism, Afterhours, and Stardust.
- Four color palettes, speed and intensity controls, favorites, and preferences that survive relaunch.
- Lock Screen and Home Screen previews, explicitly labeled as in-app previews.
- Animation lab: opening cards, a 3D flip, and a draggable spring orb; smooth, spring, snap, and drift presets; duration, bounce, and haptics.
- PNG still-image sharing, seamless QuickTime video-loop sharing, and paired JPEG/MOV Live Photo saving.
- Add-only Photos permission; no account, network requests, telemetry, purchases, or third-party dependencies.
- Respect for iOS Reduce Motion and Low Power Mode; animation pauses while the app is inactive.
- App icon, launch color, privacy manifest, shared Xcode scheme, automated test source, and optional Mac CI workflow.

## What it changes

Flux customizes its own interface and generates media you can use as wallpaper. It does not jailbreak iOS or change system app-opening animations, the status bar, other apps, or the real Home Screen icon layout. There is no fake jailbreak button or installation profile.

The Home Screen wallpaper stays still. A supported Live Photo can animate when the Lock Screen wakes. iOS determines eligibility; generated Live Photos may show “Motion Not Available.” Live Photo export and on-device wallpaper eligibility must be tested before distribution. Still-image and video exports are separate fallbacks.

## Open and run

1. On a Mac, install a current full Xcode version accepted by App Store Connect. This project uses Xcode 16-compatible project settings and Swift 5 language mode; newer supported Xcode versions can open it.
2. Open **Flux.xcodeproj** and select the **Flux** scheme.
3. Choose an iPhone simulator and press Run. Simulator builds do not need Apple signing.
4. For a physical iPhone, select the Flux target → Signing & Capabilities, set your own unique bundle identifier, and choose your Apple development team. Let Xcode manage signing.
5. Choose your connected iPhone and run. Complete any Developer Mode/device trust steps requested by Xcode or iOS.

Run the automated simulator checks from the project directory:

    bash scripts/check-mac.sh

That script runs the XCTest cases in FluxTests/FluxTests.swift. It checks preference persistence, corrupt-data recovery, visible wallpaper rendering and loop boundaries, still-image dimensions, Live Photo pairing and timed metadata, video duration, and cancellation. These XCTest cases have not been run in the Linux authoring environment.

## Get it onto TestFlight

You need an Apple Developer Program membership, a suitable App Store Connect role, a unique registered bundle ID, and a signed iOS archive. No Apple password, certificate, account, or provisioning profile is included.

1. Build and test on a physical iPhone, including saving and playing a Live Photo, trying it in Wallpaper settings, permission denial, export cancellation, VoiceOver, Reduce Motion, and Low Power Mode.
2. Set your developer team and bundle ID in Xcode. Increase the build number for each new upload.
3. Create the app record in App Store Connect using that same bundle ID.
4. In Xcode, choose a generic iOS device destination, then **Product → Archive**.
5. In Organizer choose **Distribute App → App Store Connect → Upload**.
6. After Apple processes the build, open the TestFlight tab in App Store Connect. Add the beta description, “What to Test,” real feedback email, and any required review contact information. Suggested copy is in TESTFLIGHT.md.
7. For your own team, add an eligible internal tester. For an external invitation or public TestFlight link, create a testing group, add the build, and complete Apple's beta review when required.
8. Copy the actual invitation/public link generated by App Store Connect. A link or redeem code cannot be made from source code alone.

Optional signed archive helper, after signing in to Xcode:

    export FLUX_TEAM_ID='YOUR_TEAM_ID'
    export FLUX_BUNDLE_ID='com.yourname.flux'
    export FLUX_BUILD_NUMBER='1'
    bash scripts/archive-testflight.sh

The helper archives and opens Organizer. It does not silently upload or create a testing group. It refuses to overwrite an existing build/Flux.xcarchive.

## Structure

| File | Purpose |
| --- | --- |
| Flux/RootView.swift | Studio and wallpaper gallery |
| Flux/WallpaperEditor.swift | Editor, export UI, wallpaper guide |
| Flux/MotionLabView.swift | Interactive animations |
| Flux/WallpaperRenderer.swift | Shared procedural rendering |
| Flux/WallpaperSurface.swift | Lifecycle-aware display-link view |
| Flux/WallpaperExporter.swift | Off-main-actor movie and image creation |
| Flux/ExportController.swift | Export progress, cancellation, and sharing |
| Flux/Models.swift | Persistent settings and presets |
| Flux/SettingsView.swift | Preferences and privacy explanation |
| Flux/PrivacyInfo.xcprivacy | App-local UserDefaults reason declaration |
| FluxTests/FluxTests.swift | Simulator-capable validation tests |

The wallpaper renderer is generated from vector math; no downloaded wallpaper or proprietary artwork is required.
